# BBPC Convex Migration Test Plan

Generated by engineering review on 2026-07-23.

This is the QA-facing acceptance plan for the full migration program. Production-derived
values remain on the approved encrypted development machine and must not be copied into
this file, Git, CI, screenshots, or bug reports.

## Affected Pages and Routes

### `bbpc`

- `/`, `/episodes`, `/episodes/[slug]`, and `/next` — public episode discovery and detail
  reads remain complete, ordered, and accessible without accidental private data.
- `/assignment/[slug]` — authenticated assignment review, rating, guess, gambling,
  upload metadata, and stale/concurrent submission behavior.
- `/profile`, `/history`, `/year`, and `/ratings` — canonical user identity, points,
  season boundaries, summaries, and empty states.
- `/game`, `/games`, and `/syllabus` — current-season selection, ordering, permissions,
  and reactive updates.
- Authentication, tRPC, upload, and restricted API routes — Clerk session propagation,
  compatibility error mapping, authorization, and write-gate behavior.

### `bbpc-admin`

- `/user`, `/user/[id]`, and `/role` — Phase −1 legacy protection, Clerk-linked users,
  role assignment, authorization denial, and audited impersonation.
- `/episode`, `/episode/[slug]`, `/assignment/[slug]`, `/movie`, `/movie/[id]`, `/show`,
  `/show/[id]`, `/rating`, `/tag`, and `/banger` — content CRUD, relationships,
  uniqueness, validation, and side-effect states.
- `/season`, `/season/[id]`, `/game`, `/gambling`, `/point/[id]`, and `/quotabunga` —
  canonical scoring rules, concurrency, lock states, and destructive-operation controls.
- `/lists`, `/lists/[id]`, `/admin/ranked-types`, and `/syllabus` — stable ordering,
  duplicate positions, stale edits, and concurrent reorders.
- `/azure-blobs`, upload APIs, and restricted APIs — queued side effects, retries,
  reconciliation, authorization, and redacted failures.

### `bbpc-pipeline`

- Episode lookup, metadata update, extraction, publication, thumbnail, and backfill
  workflows — Clerk M2M identity, least-privilege permissions, typed errors, retries,
  idempotency, and no SQL fallback.

### `bbpc-recording` follow-on

- Session creation/join, participant capabilities, RTC state, manifests, favorites,
  uploads, cleanup, and export — canonical episode/user linkage, regenerated capabilities,
  and migration reconciliation after the core cutover.

## Key Interactions to Verify

- Sign in through Google and email, link a verified Clerk identity to exactly one migrated
  user, sign out, reauthenticate, and handle revoked or expired sessions.
- In S2, authenticate only with migration-pre-provisioned regular-user, administrator,
  and pipeline smoke identities; prove an unlinked ordinary identity cannot write a link,
  then prove its first link succeeds only after S3.
- Deny anonymous, ordinary-user, impersonated, admin, pipeline, and recording-capability
  identities from every operation outside their explicit access class.
- Create and edit reviews, assignments, guesses, gambling entries, ranked lists, seasons,
  syllabus ordering, quote submissions, episodes, movies, shows, ratings, tags, and points.
- Submit twice, submit concurrently from two tabs, edit stale state, navigate away during
  a write, and retry after a network or backend failure.
- Translate structured Convex errors consistently through tRPC and the Python wrapper.
- Queue each external side effect once, show pending/failure state, retry safely, reconcile
  remote state, and expose an actionable operator recovery path.
- Authenticate the pipeline with Clerk M2M, reject expired/revoked/wrong-audience tokens,
  and deny permissions outside the service principal's configured operations.
- Disable application writes and prove browsers, stale builds, direct HTTP clients,
  scheduled jobs, service tokens, and side-effect dispatchers cannot bypass the gate.

## Edge Cases

- Empty tables, one-row tables, maximum production row counts, large text values, and
  values at every SQL numeric boundary.
- SQL `NULL` versus absent values, calendar dates around Pacific/UTC transitions,
  ambiguous timestamps, case-insensitive collisions, Unicode normalization, and
  whitespace-normalized unique keys.
- Duplicate legacy IDs, duplicate target keys, missing parents, orphaned joins, invalid
  enum-like strings, stale stored-procedure artifacts, and approved rejected records.
- No active season, overlapping seasons, zero and negative point boundaries, insufficient
  gambling balance, locked/resolved bets, ties, and rounding behavior.
- Interrupted extraction/import before and after checkpoints, repeated batches, out-of-order
  batches, malformed JSONL, stale transformer version, and mismatched source fingerprint.
- Portable-backup attempts containing raw staging, checkpoints, local control state,
  pending effects/jobs, or an enabled/mismatched `systemState`; missing `systemState`
  must remain default-deny until protected production initialization.
- Clerk outage, token expiry during a request, machine-token revocation, Convex timeout,
  unavailable external storage, duplicate webhook delivery, and terminal retry exhaustion.
- Old API package against a backward-compatible backend, failed package generation, failed
  consumer contract checks, and rollback to the last compatible package.

## Critical Paths

1. Verify the Phase −1 legacy authorization patch denies every previously unprotected
   mutation before Convex implementation begins.
2. Extract a fresh SQL clone, fingerprint it, import raw staging data, transform in
   dependency order, reconcile structure and behavior, scrub all non-portable state,
   prove the canonical table allowlist and zero pending effects/jobs, create a Convex
   backup, restore it to a disposable deployment, initialize a fresh disabled
   `systemState`, and rerun acceptance.
3. Run the same critical fixture through SQL and Convex and compare normalized response,
   final state, authorization, error code, and side-effect intent.
4. Sign in with Clerk as an existing user, link verified identity, perform a core write,
   observe it reactively, and verify the audit actor.
5. Execute administrator role/destructive workflows and prove ordinary, impersonated, and
   service identities cannot inherit administrator authority.
6. Run a pipeline job using Clerk M2M, retry a forced timeout, and prove exactly one
   authorized final mutation with no SQL connection.
7. Enter S1, migrate and reconcile the fresh frozen snapshot, enter S2, smoke every
   consumer read-only, force a failure, and restore SQL service without lost writes.
8. Repeat S1/S2 successfully, verify and restore the named backup, approve the go/no-go
   record, enter S3, and prove the first application/domain write makes SQL reopening
   forbidden while pre-S3 audited snapshot/control writes remain reversible.
9. After core stabilization, migrate recording data and capabilities separately, reconcile
   it, switch clients, and retire its old deployment only after acceptance passes.
