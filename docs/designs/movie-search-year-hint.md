Status: APPROVED

## Problem Statement

TMDB-backed movie search accepts a `y:YYYY` modifier, but none of BBPC's movie-search interfaces explain it. This matters because a broad title query can return no results while the same title with a release year succeeds. The concrete example is `Imposter`: adding `y:2001` finds the intended movie.

The behavior must be consistent across every TMDB movie-search surface in the public and admin applications. TV search is excluded.

## What Makes This Cool

The interface teaches the hidden modifier exactly when it can help, then lets the user apply it without copying syntax. A failed search becomes a useful next step rather than a dead end.

## Constraints

- Preserve independent deployment of `apps/web` and `apps/admin`.
- Put shared query interpretation and transformation in an explicit workspace package. Do not use cross-app relative imports.
- Reuse the existing backend `y:YYYY` support. No Convex schema or production deployment change is required.
- Do not show the hint before a valid search, while a search is loading, after TMDB fails, or when the query already contains a valid year modifier.
- Do not move keyboard focus merely because the hint appeared.
- Preserve the backend's normalized 200-character query limit when rewriting or appending syntax.

## Premises

1. A no-results response should show the year hint immediately, even when the query contains no bare year. TMDB can return a hit only after the year filter is supplied.
2. A successful search should show the hint after a three-second delay so results remain the primary content. The delayed hint is still useful when some matches are visible because the intended movie may be absent or difficult to find among them.
3. After a zero-result search, a trailing four-digit year, optionally wrapped in parentheses, should receive a specific confirmation action such as `Use 2001 as release year`. Successful searches retain the generic delayed hint so numeric movie titles such as `Blade Runner 2049` are not immediately treated as mistakes.
4. A query without a bare year should receive `Add y:year`; activating it appends ` y:` and focuses the insertion point so the user can enter four digits.
5. Live-search surfaces should pause requests while a trailing `y:` modifier is incomplete. Manual-submit surfaces should leave the Search action disabled until the modifier is complete.
6. Changing the query or media kind, starting another search, selecting a result, closing or unmounting the search surface, or receiving a stale response cancels the delayed hint.

## Landscape Check

Current search UX guidance agrees that a no-results state needs an actionable recovery path rather than a dead end. Progressive disclosure also needs stable placement so delayed controls do not cause a disruptive layout shift. The design therefore reserves a small feedback row beneath search status and above results.

## Approaches Considered

### Approach A: Passive contextual tip

Show plain instructional text immediately after zero results and after three seconds when results exist. Rejected because it still asks users to understand and manually type unfamiliar syntax.

### Approach B: Actionable contextual hint

Use the same timing, but provide a keyboard-accessible action that rewrites a detected bare year or starts a `y:` modifier. Chosen because it teaches through use while keeping the normal search interface uncluttered.

### Approach C: Separate release-year field

Add a permanent optional year control beside every movie search. Rejected because it adds interface weight to an occasional disambiguation task and makes the new query modifier largely redundant.

## Recommended Approach

Create a private, source-exported workspace package named `@bbpc/movie-search-hints` for the shared policy:

- Export TypeScript source directly from `src/index.ts`; both Next applications add the package to `transpilePackages` and depend on it via `workspace:*`.
- Detect complete, incomplete, duplicate, conflicting, and malformed year syntax without changing the backend's validation semantics.
- Detect a trailing bare four-digit year, including `(2001)`, only when title text remains after removing it.
- Rewrite a confirmed bare year to `y:YYYY` while preserving title text and normalization.
- Append an incomplete ` y:` only when the resulting normalized query stays within 200 characters.
- Export the three-second successful-result delay, a pure function that returns timer eligibility, and a headless React hook that owns delayed reveal and cleanup.

The shared hook owns the timer lifecycle and resets when the request generation, request query, current input, media kind, phase, TMDB status, or visible-result count changes. It destructures those primitive fields and lists them explicitly as effect dependencies; it never depends on the caller's input-object identity or require callers to memoize that object. Its effect cleanup cancels the timer on dependency changes and unmount, including React Strict Mode's development setup-cleanup cycle. Each application owns its visual wrapper and input ref so it can keep its existing component system. The hint appears directly below the search status and before the result grid or list. After a search settles, that row reserves enough height for the complete hint: one line plus its action on wider screens and a two-line stacked treatment on narrow screens. Delayed appearance therefore does not move the results at either breakpoint.

Copy and action:

- Successful results after three seconds: `Looking for a specific release?` with `Add y:year`.
- No results immediately: `No available movie results for “{query}.” Try adding the release year.` with `Add y:year`.
- Bare year detected after zero results: `Search by release year instead.` with `Use YYYY as release year`.

When `Use YYYY as release year` is activated, rewrite the query and rerun search. When `Add y:year` is activated, append ` y:`, focus after the colon, and wait for four digits before searching. Both action handlers commit the controlled input state inside React DOM's `flushSync`, then call `focus()` and `setSelectionRange()` against the updated DOM value. Keep this synchronous render isolated to these low-frequency button actions. If appending would exceed 200 normalized characters, show the teaching copy without an action. The action is a real button, is reachable by keyboard, and has an accessible name that explains the result.

Apply the behavior to:

- Public syllabus movie search.
- Public add-extra movie search when the selected kind is movie.
- Admin TMDB movie catalog search when the selected kind is movie.
- Admin episode-assignment TMDB movie picker.

Do not apply it to show search, catalog-only search, loading states, or TMDB error states.

Approved interaction sketch: `docs/designs/assets/movie-search-year-hint.png`. The asset matches the placement and copy specified here; the written state contract remains authoritative for responsive details.

## Exact Query Grammar

The frontend analyzer normalizes with `trim().normalize("NFKC")`, matching the backend. Its expectations are:

- A complete modifier is whitespace-delimited `y:` followed by exactly four digits.
- Years `1000` through `9999` are valid. `y:0001` is complete but invalid and remains subject to the existing backend validation error.
- Repeated copies of the same valid modifier are accepted because the backend accepts them. Distinct complete modifiers such as `y:2001 y:2002` are conflicting and remain subject to backend validation.
- A trailing `y:`, `y:2`, `y:20`, or `y:200` is incomplete. Clients suppress search until the fourth digit is entered.
- Tokens such as `y:abcd` and `y:20010` are malformed, not incomplete, and keep the backend's current behavior as ordinary query text. They map to frontend `syntax: "invalid"` only to suppress a misleading second year hint; the search request still runs and the analyzer must not throw.
- A release-year candidate is the final standalone `YYYY` or `(YYYY)` token. It is offered as a rewrite only after zero results and only when removing it leaves nonempty title text. A title made solely of digits, such as `1917`, is never rewritten.
- If multiple bare-year candidates exist, only the final token is offered; the button names the chosen year so the user confirms the interpretation.
- `syntax: "searchable"` means no modifier or one repeated valid year; `syntax: "incomplete"` means a trailing numeric `y:` prefix with zero through three digits; and `syntax: "invalid"` means an out-of-range complete modifier, conflicting complete modifiers, or malformed year-like token. Only `"incomplete"` suppresses requests. `"invalid"` queries still run so existing backend ordinary-text behavior or validation errors remain intact, but they never receive another year hint.
- A complete valid modifier suppresses every year hint.

Shared conformance fixtures cover these cases and are exported from the new package's test-only `@bbpc/movie-search-hints/conformance-fixtures` subpath. The Convex package declares a workspace development dependency and consumes that subpath only from `catalogExternalApi.test.ts`; production Convex modules must not import it. This keeps the frontend analyzer aligned with `prepareTmdbSearchInput` without cross-package relative imports, moving production backend parsing, or requiring a Convex deployment.

## Shared Package Contract

```ts
export const MOVIE_YEAR_HINT_DELAY_MS = 3_000;

export type MovieYearQueryAnalysis = {
  normalizedQuery: string;
  syntax: "searchable" | "incomplete" | "invalid";
  hasValidModifier: boolean;
  releaseYearCandidate: number | null;
  canAppendModifier: boolean;
};

export type MovieYearHint =
  | { kind: "hidden" }
  | { kind: "immediate-add"; actionable: boolean }
  | { kind: "immediate-rewrite"; year: number }
  | { kind: "delayed-add"; delayMs: number; actionable: boolean };

export type MovieYearHintInput = {
  mediaKind: "movie" | "show";
  currentInput: string;
  requestQuery: string;
  phase: "idle" | "searching" | "settled";
  tmdbStatus: "not-run" | "fulfilled" | "rejected";
  visibleResultCount: number;
};

export type MovieYearHintAction =
  | { kind: "append" }
  | { kind: "rewrite"; year: number };

export function analyzeMovieYearQuery(query: string): MovieYearQueryAnalysis;

export function deriveMovieYearHint(input: MovieYearHintInput): MovieYearHint;

export function useMovieYearHint(
  input: MovieYearHintInput & { requestGeneration: number },
): MovieYearHint;

export function applyMovieYearHint(
  query: string,
  action: MovieYearHintAction,
): { query: string; caret: number; rerun: boolean } | null;
```

`deriveMovieYearHint` returns `delayed-add` only when a timer may start. `useMovieYearHint` owns elapsed time, returns `hidden` until the delay completes, and re-checks the same request query and generation before revealing the hint. Immediate hints pass through without a timer. Application code resets the request phase after result selection or surface close; unmount cleanup is automatic.

## Surface Integration Matrix

| Surface | Search mode | Settled visible results | TMDB status | Rerun and reset rules |
|---|---|---|---|---|
| Public syllabus | Live, 300 ms debounce, minimum 2 characters | Combined catalog and TMDB results after missing poster/date, duplicate TMDB ID, and already-on-syllabus filtering | Existing `externalSearchUnavailable` from `Promise.allSettled` | Setting the rewritten input reruns through debounce; input edits, result selection, close, unmount, and generation mismatch reset |
| Public add-extra | Live, 300 ms debounce, minimum 2 characters | Combined catalog and TMDB results after missing poster/date and catalog duplicate filtering | Existing `externalUnavailable` from `Promise.allSettled` | Setting the rewritten input reruns through debounce; input edits, movie/show changes, result selection, navigation, unmount, and generation mismatch reset |
| Admin TMDB catalog panel | Manual submit, minimum 3 characters | Returned TMDB movie rows, including posterless rows already supported by the panel | Add persistent fulfilled/rejected status instead of relying only on a toast | Add a request generation guard; the rewrite action invokes the same search runner with the transformed query argument; input edits, movie/show route changes, unmount, and generation mismatch reset |
| Admin episode-assignment TMDB picker | Manual submit, minimum 3 characters | Returned TMDB movie rows | Add persistent fulfilled/rejected status so a failed request cannot render as zero results | Add a request generation guard; the rewrite action invokes the same search runner with the transformed query argument; every input edit or hint action clears the selected movie; selection, dialog close, unmount, and generation mismatch reset hint state |

Every response is associated with its normalized request query and generation. A response may update results or hint state only if both still match the current input and active generation.

`visibleResultCount` deliberately means the final actionable result set after each surface's existing metadata, deduplication, and already-added filters. Raw TMDB matches do not suppress the hint: zero visible results receives immediate recovery, while one or more visible results receives delayed recovery because the intended movie may still be missing or hard to find. Component tests include filtered-to-zero responses so this behavior remains intentional.

Both manual admin surfaces refactor their search command to accept the normalized request query explicitly. Search-button and Enter handlers pass the analyzed current input; a rewrite action passes `applyMovieYearHint(...).query` directly after updating the controlled input. The command never re-reads query state from the render closure, so the automatic rerun cannot use the pre-rewrite value.

Each surface stores search output as one settled request snapshot containing generation, normalized request query, media kind, TMDB status, and visible results. Results, empty copy, and hints render only when that snapshot still matches the current normalized input, media kind, and active generation. Every raw input or kind edit increments the generation immediately, even before a live-search debounce settles, so previous results become non-current at once. Incomplete `y:` input therefore hides stale results while pausing the next request; it does not need scattered result-array clearing calls.

The assignment movie picker also clears its selected movie on every raw search-input edit and on either hint action. Its parent therefore disables `Add assignment` until the user selects a result associated with the current search. Query text and selected submission data can never silently contradict each other.

## Accessibility and Focus

- Delayed successful-result hints are not placed in an `aria-live` region; appearing help should not interrupt a user reading results.
- The immediate no-results message uses the surface's existing polite search status or status role. The action button follows it in normal tab order.
- Hint appearance never moves focus. Activating either action moves focus to the search input after updating it.
- A rewrite places the caret at the end and reruns search. An appended incomplete modifier places the caret after `y:` and does not search until four digits are present. The controlled value is synchronously committed before either focus or selection is applied.
- When a focused action disappears after activation, focus has already been moved to the input. Query edits or timer cancellation do not move focus.
- The hint uses no entrance animation, so reduced-motion behavior needs no exception.

## Interaction State Table

| Search state | Hint behavior |
|---|---|
| Query too short or incomplete trailing `y:` | Hidden; suppress search and hide any non-current settled result snapshot |
| Searching | Hidden; cancel any prior timer |
| TMDB failed | Hidden; preserve the existing error message |
| Complete `y:YYYY` present | Hidden |
| Malformed `y:abcd` or `y:20010` | Run search as today; hide year hint even after zero results |
| Invalid `y:0001` or conflicting complete modifiers | Run search so existing validation appears; hide year hint |
| Zero results and trailing bare year present | Immediate `Use YYYY as release year` action |
| Zero visible results after search settles | Immediate `Add y:year` action |
| One or more visible results after search settles | Show `Add y:year` after three seconds |
| Query/kind changes, stale response, result selection, close, or unmount | Increment generation; hide non-current results; cancel and reset the hint |

## Success Criteria

- `Imposter` with zero results immediately offers `Add y:year`.
- A TMDB response whose rows are all filtered out still uses the immediate available-results copy and hint.
- `Imposter (2001)` with zero results immediately offers `Use 2001 as release year`; activation produces `Imposter y:2001` and reruns search.
- A successful `The Imposter` search shows no hint for three seconds, then offers `Add y:year` without shifting existing results or focus.
- A successful `Blade Runner 2049` search receives only the generic delayed hint, while a sole numeric title such as `1917` is never offered as a rewrite.
- A complete query such as `Imposter y:2001` never shows the hint.
- An incomplete trailing `y:` does not trigger a request.
- Invalid, duplicate, conflicting, malformed, Unicode-normalized, and 200-character-boundary queries follow the exact grammar above without throwing or bypassing backend validation. Fixtures assert both request gating and hint outcome for every case.
- A TMDB failure is not presented as a genuine no-results state and never shows the hint.
- TV searches never show the movie-year hint.
- All four movie-search surfaces use the same shared parsing, transformation, timing constant, and state rules.
- Unit tests cover parsing, numeric titles, parenthesized years, rewriting, incomplete and malformed syntax, duplicate/conflicting modifiers, maximum length, zero results, successful-result delay, cancellation, kind changes, stale responses, unmount, and error suppression.
- `packages/movie-search-hints/src/index.test.tsx` covers the pure analyzer, policy, transformation, conformance-fixture export, and headless hook with Vitest fake timers, including React Strict Mode setup-cleanup behavior.
- `apps/web/tests/MovieSearchYearHints.behavior.test.tsx` renders the public syllabus and add-extra integrations with mocked Convex searches in the existing Node-environment Vitest suite. React test-renderer's `createNodeMock` supplies input nodes with controlled `value`, `focus`, and `setSelectionRange` spies, and the suite mocks `flushSync` as an immediate callback. It proves request gating, fulfilled/rejected status, visible-result counts, delayed cancellation, movie/show changes, stale generations, action rewrites, reruns, and focus/selection call ordering; it does not claim to emulate browser-native selection behavior.
- `apps/admin/src/components/MovieSearchYearHints.behavior.test.tsx` gives the two admin integrations the same explicit Node/test-renderer harness and behavioral coverage. Admin adds the React 18 test renderer and matching types as development dependencies; no DOM test environment or Testing Library dependency is introduced.
- Existing source-contract tests remain as boundary checks, but they do not substitute for the new behavioral suites.
- One browser pass across all four surfaces verifies real DOM caret placement, keyboard operation, three-second timing, stable responsive layout, and the live `Imposter` recovery flow.

## Distribution Plan

The existing Vercel deployment pipelines for the public and admin applications cover the UI changes. `@bbpc/movie-search-hints` is private, source-exported, referenced with `workspace:*`, declares the applications' existing React 18 version as a peer dependency, and is transpiled by both Next applications; it is not published separately and needs no standalone build artifact. Its package exports expose the runtime entry point and a separate test-only conformance-fixture subpath. Root check and test scripts explicitly run its typecheck and Vitest suite before the applications so CI cannot omit it. The Convex package uses the fixture subpath through a workspace development dependency. The existing guarded Convex deployment workflow is unaffected because production backend code does not change.

## Dependencies

- Existing `prepareTmdbSearchInput` support for `y:YYYY`.
- Existing search loading, results, error, and query state in each client surface.
- No new third-party dependency.

## What Already Exists

- `packages/convex-backend/convex/catalog/tmdbClient.ts` already normalizes TMDB queries, enforces the 200-character limit, extracts whitespace-delimited `y:YYYY`, accepts repeated copies of the same year, and rejects out-of-range or conflicting complete modifiers. The new package mirrors and tests this contract rather than replacing the production parser.
- `ConvexSyllabusManager.tsx` and `ConvexAddExtraPageClient.tsx` already use generation guards and `Promise.allSettled` to keep catalog matches usable when TMDB rejects. Their existing generation and external-status state are extended rather than rebuilt.
- `ConvexMediaCatalogPage.tsx` and `TmdbMoviePicker` already own their manual-submit queries, loading state, result rendering, and error toasts. They need persistent request status and generation guards so failures and stale responses cannot masquerade as current empty results.
- The web application already has a Vitest, React test-renderer, and fake-timer behavior-test pattern. The admin application already uses Vitest and adds the matching React 18 renderer only for these component-behavior tests.
- Next.js provides `transpilePackages`, pnpm provides `workspace:*`, and the existing Vercel pipelines build each consuming application. No custom bundler or publishing workflow is introduced.

## NOT in Scope

- TV/show search hints. The backend modifier and recovery example are movie-specific.
- A permanent release-year field or advanced-search panel. The approved interaction stays contextual.
- Moving `prepareTmdbSearchInput` into the new package or changing production Convex parsing, schema, functions, deployment targets, or environment checks.
- A shared visual component across the public and admin design systems. Only headless behavior is shared.
- A new automated Playwright harness. Focused component tests and the required manual browser pass ship here; reusable authenticated browser infrastructure is captured as a P3 item in `TODOS.md`.
- Search-result caching, prefetching, analytics, experimentation, or changes to TMDB ranking.
- Publishing `@bbpc/movie-search-hints` outside this private pnpm workspace.
